# Damodaran Website Archive — Crawl & Conversion Runbook

**Audience:** a fresh Claude Code session on a GPU machine. This document is self-contained — read it top to bottom, then execute the phases in order. Nothing else is required except this repo and the dependencies listed below.

**Goal:** download all of Damodaran's website (pages.stern.nyu.edu/~adamodar/) plus directly-linked external PDFs/XLS, convert everything to Claude-readable markdown, and organize it under this folder (`03-corporate-finance/03-5-damodaran-online/`) with the repo's standard CLAUDE.md navigation.

**Design principles:**
- **Local-first.** Everything runs on this machine. No GitHub Actions in the critical path (6-hour job limits and API costs make bulk CI runs a bad fit).
- **GPU for PDFs.** [marker](https://github.com/VikParuchuri/marker) is the primary PDF→markdown converter (free, fast on GPU). Claude vision API is the *fallback only*, for pages marker mangles — this keeps API cost bounded.
- **Gate before you spend.** Phase 0 is a manifest-only dry run. Do not start downloading or converting until its report has been reviewed.
- **Resumable everywhere.** Every script must be idempotent (skip completed work unless `--force`) and safe to interrupt. Log per-file status to a progress JSON.

**Repo conventions you must follow (enforced by hooks/CI):**
- All filenames and folders: **kebab-case** (lowercase, digits, single hyphens). `CLAUDE.md`, `README.md`, `LICENSE` are the only ALL-CAPS exceptions. A PreToolUse hook blocks non-compliant Write/Edit.
- Every non-`CLAUDE.md` markdown file needs frontmatter: `title`, `status: active`, `owner: weprintmoney`, `created`, `last_updated` (YYYY-MM-DD), plus `source_url` for converted content.
- **Never read a `.mp4`** — they are Git LFS pointers. (This crawl does not download videos at all; see skip rules.)
- When you add files to a folder that has a `CLAUDE.md`, update that `CLAUDE.md`'s doc index.
- Direct push to `main` is blocked: branch → PR → **admin merge** (`gh pr merge <N> --admin --merge --repo weprintmoney/corporate-finance-automation`). Sole-contributor repo; admin merge without asking is the standing rule.
- Existing scripts in `scripts/` are stdlib-first Python (urllib, json) — match that style; import third-party libs conditionally with a helpful error message.

## Phase 0 — Dry-run crawl (scale gate)

Write `scripts/crawl-damodaran-site.py`, then run it with `--dry-run` first.

**Dry-run behavior:** crawl HTML pages only (follow links breadth-first within `pages.stern.nyu.edu/~adamodar/`), but do **not** download PDFs/XLS — instead issue HEAD requests to record `Content-Length` and `Content-Type`. Build `scripts/crawl-manifest.json`:

```json
{
  "generated": "YYYY-MM-DDTHH:MM:SSZ",
  "entries": [
    {"url": "...", "type": "html|pdf|xls|video|other", "bytes": 123456,
     "status": "pending", "local_path": null, "discovered_on": "referring page URL"}
  ]
}
```

**Then print a report:** file counts and total bytes by type, estimated PDF page count (assume ~60 KB/page if unknown), estimated marker runtime on GPU (~1–2 s/page), and a vision-fallback cost band assuming 5–15% of pages fall back (≈ $0.01–0.02/page with claude-sonnet-4-6).

**Decision gates — resolve with the user before Phase 1:**

| Gate | Question | Action |
|------|----------|--------|
| a | Total XLS/binary bytes > ~300 MB? | Extend Git LFS to `*.xls *.xlsx` in `.gitattributes` (free tier = 1 GB storage/bandwidth — if totals approach that, discuss before proceeding) |
| b | PDF volume (pages) | Confirm marker runtime is acceptable; if tiny (< 500 pages), vision-only is also fine |
| c | Anything unexpectedly huge (> 1 GB total) | Rescope with the user before downloading |

**Crawler requirements (both modes):**
- stdlib `urllib` only, 0.5 s delay between requests, honor `robots.txt`
- Scope: everything under `pages.stern.nyu.edu/~adamodar/`, plus *directly linked* off-domain PDFs/XLS (one hop — never crawl external HTML)
- **Skip:** video files (record URL + title in manifest as `type: video` for later stub generation), images, and blog posts — dedupe blogs by slug against `03-corporate-finance/03-4-blogs/posts/` (~680 posts already archived)
- Idempotent: on rerun, skip URLs already fetched to `.crawl-cache/` unless `--force`

## Phase 2 — Conversions

Three scripts, all driven by `crawl-manifest.json`, all idempotent (skip when output exists unless `--force`), all logging per-file results to `scripts/convert-progress.json`.

### 2a. `scripts/convert-damodaran-html.py`

- Library: `markdownify`
- For each `type: html` entry: convert to markdown, strip nav boilerplate, write to the folder given by the URL classification map below
- Frontmatter on every output: `title`, `status: active`, `owner: weprintmoney`, `created`, `last_updated`, `source_url`

**URL-path → folder classification:**

| URL pattern | Destination |
|-------------|-------------|
| `/pc/datasets/`, `/New_Home_Page/data*` | `03-5-1-datasets/` |
| Course pages (`cf*.htm`, `val*.htm`, and similar course hubs) | `03-5-2-course-materials/<course>/` |
| `/pdfiles/` | `03-5-3-papers/` |
| `/New_Home_Page/spreadsheets/` | `03-5-4-tools/` |
| Book pages | `03-5-5-books/` |
| Unmatched | Log to `scripts/unclassified.json`; classify manually at the end — do not guess silently |

Video entries in the manifest get a **stub .md** (title, one-line description, external URL) in the appropriate folder — never download the video itself.

### 2b. `scripts/convert-damodaran-xls.py`

- Libraries: `xlrd` (legacy .xls) + `openpyxl` (.xlsx) — same pair `scripts/fetch-damodaran.py` already uses; follow its import pattern
- Per workbook, produce `{slug}/` containing:
  - `{slug}.md` — header (title, `source_url`, sheet list, one-paragraph description of what the workbook contains), then per sheet: **≤ 200 rows → inline markdown table; > 200 rows → first-20-row preview + note pointing at the CSV**
  - `{slug}-{sheet}.csv` — full export for each large sheet
  - Original `.xls`/`.xlsx` copied alongside
- Slugs: kebab-case from the filename (e.g. `betas.xls` → `industry-betas/` if the page context names it that; else `betas/`)

### 2c. `scripts/convert-damodaran-pdfs.py` (GPU)

- **Primary: marker.** Run marker on each PDF (`marker_single` API or CLI). Fast path; free.
- **Per-page QA heuristic** on marker output — route a page to fallback when any of:
  - Empty or near-empty output for a non-blank page
  - Garbled-text ratio high (e.g., > 20% non-dictionary character sequences / mojibake)
  - Page has embedded images/charts (detect via pymupdf `page.get_images()`) but the markdown contains no corresponding description or table
- **Fallback: Claude vision.** Render the page to PNG via pymupdf, send to `claude-sonnet-4-6` with:
  > "Convert this page of a Damodaran finance/valuation document to clean markdown. Reproduce all tables. Describe every chart, graph, and diagram in detail — axes, series, and the point the visual is making."
  Splice the fallback page back into the document in order. Requires `ANTHROPIC_API_KEY`; if unset, log the page as `needs_vision` and continue rather than failing.
- Output per PDF: `{slug}.md` with frontmatter + `---` page separators, in the classified folder
- Track in progress JSON: pages converted, pages fallback-routed, cost estimate

**Verify on samples before the bulk run** (see Verification below).

## Phase 3 — Navigation build

Write and run `scripts/build-damodaran-index.py` after every crawl/convert cycle:

1. Scan everything under `03-5-damodaran-online/`
2. Generate `content-index.yaml` — schema mirrors `03-2-course-content/lesson-index.yaml`:

```yaml
resources:
  - slug: industry-betas
    category: datasets            # datasets | course-materials | papers | tools | books
    title: "Industry Betas (January 2026)"
    source_url: "https://pages.stern.nyu.edu/~adamodar/pc/datasets/betas.xls"
    folder: 03-5-1-datasets/industry-betas
    files: {markdown: true, csv: true, original: true}
```

3. Generate/refresh `03-5-damodaran-online/CLAUDE.md`: overview paragraph, doc-index table pointing to each sub-`CLAUDE.md` + `content-index.yaml` + this runbook, and a note that videos are stubs and blogs live in `03-4-blogs/`
4. Generate one `CLAUDE.md` per `03-5-1..5` subfolder with a doc-index table (file | one-line description)

Target navigation: root `CLAUDE.md` → `03-corporate-finance/CLAUDE.md` → `03-5-damodaran-online/CLAUDE.md` → resource, in ≤ 3 hops.

## Phase 4 — Commit

- Confirm `.gitignore` contains `.crawl-cache/` (add if missing)
- Apply the Phase 0 LFS decision: if gated in, add `*.xls filter=lfs diff=lfs merge=lfs -text` (and `.xlsx`) to `.gitattributes` **before** staging binaries
- Update `03-corporate-finance/CLAUDE.md` doc index if new top-level files appeared
- Commit in reviewable batches — one branch/PR per `03-5-*` subfolder if the archive is large; single PR if small
- Each: branch → `gh pr create` → `gh pr merge <N> --admin --merge --repo weprintmoney/corporate-finance-automation`
- Sanity-check repo size before/after: `git count-objects -vH`

## Verification checklist

1. **Phase 0:** dry-run report reviewed and gates resolved before any download
2. **XLS sample:** convert one workbook → inspect markdown table formatting, CSV export, frontmatter
3. **PDF sample:** run one chart-heavy PDF (e.g., an ERP paper) through marker → confirm the QA heuristic routes chart pages to the vision fallback and the fallback output actually describes the charts
4. **Index:** run `build-damodaran-index.py` → `content-index.yaml` parses, every resource folder is listed, all `CLAUDE.md` files regenerate cleanly
5. **Navigation:** in a fresh Claude session, navigate from root `CLAUDE.md` to a specific dataset in ≤ 3 hops
6. **Hygiene:** `git status` clean of `.crawl-cache/`; no non-kebab-case filenames; spot-check frontmatter on a few converted files
