# /value-company

One run produces a complete course project for one company: the Module 1 cost-of-capital inputs, the Module 2–4 cumulative-project answers, a DCF and relative valuation, a report, and a walkthrough a reader with no finance background can follow from start to finish.

All paths below are relative to the repo root. `<CC>` means `03-corporate-finance/03-2-course-content`.

## What a run produces

```
<CC>/company-valuations/<slug>/
  README.md             company context, source key, corrections log, file map
  inputs.yaml           the ledger: every input number with its source and date
  sources/              compiled filings, peer filings, market data, plus sources/README.md
  lesson-01.md … lesson-36.md   question log with answers, one file per lesson
  model-output.md       generated by tools/model.py; never hand-edited
  valuation-report.md   the deliverable
  walkthrough.md        plain-language trail, one section per step, appended as the run goes
```

Supporting files in this skill folder:

| File | What it is |
|---|---|
| `question-bank.yaml` | Every question the course asks, tagged by lesson, layer, inputs needed, and company types it applies to. Generated; do not edit by hand. |
| `ledger-schema.yaml` | Every field `inputs.yaml` can hold, with what it means and which lessons use it. |
| `source-plans.md` | Where each ledger field comes from, per company type. |
| `walkthrough-template.md` | The fixed section shape and the plain-language rules for `walkthrough.md`. |
| `review-checklist.md` | The adversarial pass run before the report is final. |
| `tools/build-question-bank.py` | Rebuilds `question-bank.yaml` from the lesson files and the seeds. |
| `tools/validate-ledger.py` | Checks `inputs.yaml` for missing fields, missing sources, and broken identities. |
| `tools/model.py` | Cost of capital, optimal debt, value of moving, FCFE vs. cash returned, DCF, multiples. |
| `tools/check-walkthrough.py` | Confirms every number in `walkthrough.md` traces to the ledger or the model output. |
| `examples/solarwinds-inputs.yaml` | A test fixture for the tools, not a reference valuation. Its real figures cite the SolarWinds project files in this repo; the rest are marked `source: placeholder`. |

## Rules that hold for the whole run

1. **Ledger first.** No number appears in a lesson answer, the report, or the walkthrough unless it is in `inputs.yaml` (an input) or `model-output.md` (a computed result). If a step needs a number that isn't there yet, add it to the ledger with its source, then use it.
2. **Run the model after every ledger change.** `python3 .claude/skills/value-company/tools/model.py <CC>/company-valuations/<slug>/inputs.yaml > <CC>/company-valuations/<slug>/model-output.md`. Lesson answers quote the model output; they do not recompute by hand.
3. **Walkthrough sections are written when the step is done, not at the end.** Each phase below says when to append. Follow `walkthrough-template.md` exactly.
4. **Corrections go to the ledger, then forward.** When a later step finds an earlier number wrong: fix `inputs.yaml`, rerun the model, add a dated line to the corrections log in `README.md`, and add a dated note under the affected lesson answers. Do not silently rewrite earlier answers.
5. **Company type gates the questions.** Each question-bank entry lists `applies_to`. Skip entries that don't apply to this company's type, and say in the lesson file that they were skipped and why.
6. **Never read `.mp4` files.** Transcripts are the `.md` with the same stem.
7. **Sources are documents, not search results.** A fact from a filing is cited to the file in `sources/` and the note or section inside it. A fact from the web is fetched, saved into `sources/`, and cited from there.
8. **Branch, PR, admin merge.** Direct push to `main` is blocked.
9. **No placeholders.** A number that can't be sourced is omitted (listed under `meta.omitted`) or marked `estimate: true` with a range and a source that says what the estimate rests on. `source: placeholder` exists only for the skill's test fixture; the validator rejects it anywhere else.

## Scope argument

`/value-company <company> [scope]` where scope is `module-1`, `through-module-2`, `through-module-3`, or `full` (default `full`). `module-1` is what the old `/evaluate-company` command delivered.

## Resuming

The artifacts on disk are the state. To resume: read `README.md`, `inputs.yaml`, the last `lesson-NN.md` present, and the tail of `walkthrough.md`, then continue from the next lesson. A full run is large; one module per session is a reasonable pace.

## Phase 0: Profile

Ask once: **"Which company?"** Then, from the company's own filings or site, settle:

- Name, ticker or none, legal form, home country, reporting currency, fiscal year end.
- **Type**: `public` (listed, files with a regulator), `delisted` (filings exist up to a date, no live price), `private` (no public filings), `foreign-public` (listed outside the US).
- **Base year**: the latest full fiscal year with a complete set of statements.
- **Analysis currency** and the reason (lesson 5).
- Any event that changes how the numbers should be read (pending sale, recent spin-off, restatement).

Write:
- `<slug>/README.md` with the context paragraph, the file map, an empty corrections log, and the source key (copy the structure from `company-valuations/solarwinds/README.md`).
- `<slug>/inputs.yaml` with the `meta` block filled and the `modeling_choices` block set to the defaults in `ledger-schema.yaml`.
- `<slug>/walkthrough.md` with the title, the "how to read this" paragraph from the template, and an empty summary placeholder. The summary is written last.

**Pause.** Show the profile and ask for a yes before compiling sources.

## Phase 1: Sources

Follow `source-plans.md` for the company's type. Produce:

- `sources/<group>/<file>.md` for each document (filings, peer filings, market data), converted to markdown.
- `sources/README.md`: a manifest listing every file, what it is, where it came from, and when it was fetched. Also list what could not be obtained and why.
- Market data snapshot: risk-free rate, mature-market ERP, country risk premiums, industry betas, the ratings-to-spread table. Each with its fetch date. Check `03-corporate-finance/03-3-supplemental-data/` first; if a file is missing or its data block is empty, fetch directly and say so in the manifest.

Append to `walkthrough.md`: a short section called "Where the numbers come from" that names each group of documents in plain words.

## Phase 2: Ledger

Fill `inputs.yaml` from the sources. Every input leaf is `{value, source, as_of}`. Then:

```
python3 .claude/skills/value-company/tools/validate-ledger.py <slug>/inputs.yaml
python3 .claude/skills/value-company/tools/model.py <slug>/inputs.yaml > <slug>/model-output.md
```

Fix every validator failure before moving on. Fields the company type can't supply (no regression beta for a private company) are left out and the omission is listed under `meta.omitted` with a one-line reason.

## Phase 3: Module 1 (lessons 1–12)

For each lesson 1–12, in order:

1. Read `<CC>/<module-folder>/lesson-NN/lesson-overview.md` and `slides.md`. Read a transcript only when a transcript-layer question needs the lecture's reasoning.
2. Load the question-bank entries for that lesson. Answer every applicable entry from the ledger and sources. Transcript-layer entries carry a template with `{company}`; write the question for this company, then answer it.
3. Write `lesson-NN.md` using the lesson file format below.
4. Append the lesson's walkthrough section.

After lesson 12, rerun the model and check the cost-of-capital summary in `model-output.md` against the lesson answers.

**Pause** if scope is `module-1`. Otherwise continue.

## Phase 4: Modules 2–4 (lessons 13–36)

Same four steps per lesson. Lessons 18, 19, 26, 30, 31, 32, 33, 34 and 35 are the ones whose answers lean on `model-output.md`; quote it, don't recompute. Module 4 forecasting fields (`forecast.*`) are filled in the ledger as lessons 30–32 settle them, with the model rerun each time.

**Pause** at the end of lessons 19, 26 and 36.

## Phase 5: Report

Write `valuation-report.md`: a synthesis, not a concatenation. Sections, in order: company and story; cost of capital; investment returns; financing mix and the path to the optimum; dividend policy; DCF (status quo and optimal); relative valuation; final narrative. Every number cites the ledger or the model output. The report is the deliverable; the lesson files are the working.

## Phase 6: Review

1. Spawn a fresh-context subagent with `review-checklist.md`, the company folder, and nothing else. It returns findings with file and line.
2. Run `python3 .claude/skills/value-company/tools/check-walkthrough.py <slug>/walkthrough.md <slug>/inputs.yaml <slug>/model-output.md`. Every unmatched number is either fixed in the walkthrough or added to the ledger with a source.
3. Spawn a second fresh-context subagent with only `walkthrough.md` and the instruction: "Read this as someone who has never studied finance. List every term, step, or jump you could not follow." Rewrite what it flags.
4. Apply corrections per rule 4. Write the walkthrough summary (the one-page "valuation in ten sentences") and the glossary.

## Phase 7: Ship

Update `<CC>/company-valuations/<slug>/README.md`'s file map, the doc index in `<CC>/CLAUDE.md` if a new folder was created, and open a PR. Admin merge after the checks pass.

## Lesson file format

```markdown
---
title: "<Company> (<TICKER>) — Lesson NN: <Lesson title>"
status: active
owner: weprintmoney
created: YYYY-MM-DD
last_updated: YYYY-MM-DD
---

# <Company> (<TICKER>) — Lesson NN: <Lesson title>

### Lesson NN — <Lesson title>

- **Lesson NN, Session NN · Part P — "<Part title>"** ([transcript](<relative path>))
    - Quote: "<verbatim line>"
    - Question for <Company>: <the instantiated question>
    - Sources needed: <what data answers it>
    - Where to find: <files in sources/, ledger fields>
    - Answer: <the answer, numbers cited to ledger fields or model-output.md>

## Cumulative Project — Questions for This Lesson

- **<Project question verbatim>**
  <answer>

## Skipped

- <entry id>: <why it doesn't apply to this company type>   (omit the section if nothing was skipped)

## Notes

<What this lesson established for this company, what it changed from earlier lessons, what later lessons will use.>
```

Lessons 1–12 have no `## Cumulative Project` section in their overviews; for those lessons the Module 1 step questions from the question bank fill that role under a heading `## Module 1 Step — Questions for This Lesson`.

## Walkthrough

Every section follows `walkthrough-template.md`. The template is the contract: six parts, same order, every time.
